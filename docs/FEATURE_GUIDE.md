# 医院业务管理系统 · 当前功能说明

> 版本：V1.0（本地检查点 `0c58921` + 本说明文档）  
> 更新时间：2026-11-13  
> 适用对象：演示、验收、交接与后续开发

---

## 1. 系统定位

本项目是一个**纯前端医院业务管理系统演示 SPA**，覆盖「基础资料 → 患者服务 → 门诊 → 住院 → 收费/发药 → 系统管理」的完整业务链路，并在其上叠加了智能待办、规则提醒、操作审计、患者全流程时间线、分角色工作台与 AI 只读分析能力。

- **无后端、无数据库、无真实 API**：请求由 Mock.js 拦截，数据写入浏览器 `localStorage`。
- **全部数据为虚构演示数据**：不处理真实患者信息，不作为生产医疗系统使用。
- **AI 为本地确定性引擎**：零外部网络、零密钥，只做只读分析与建议，不修改业务数据。
- **可关闭、可审计、可追溯**：AI 调用写入 `aiEvents`，业务操作写入 `auditEvents`。

## 3. 角色与权限

系统内置 5 个角色，登录后菜单、工作台、快捷入口和数据范围按角色收敛。

| 角色 | 可见菜单范围 | 工作台重点 |
| --- | --- | --- |
| 超级管理员 | 全部菜单 | 全院运营概览、低库存、待收费、待结算、审计与配置 |
| 门诊医生 | 首页、患者服务、门诊管理、AI 助手/预测 | 本人待接诊、本人待出报告、我的待办 |
| 挂号收费员 | 首页、患者服务、门诊挂号、门诊收费、AI 助手/预测 | 待收费、待发药、待结算 |
| 住院医生 | 首页、患者服务、住院管理、AI 助手/预测 | 待入科、待执行医嘱、待结算 |
| 护士长 | 首页、床位/病区、住院管理、AI 助手/异常/预测 | 床位与医嘱执行相关队列 |

权限链路为**演示级纵深防御**：

1. 侧栏菜单按角色过滤；
2. 路由 `meta.menuCode` 守卫，越权跳 `/403`；
3. Mock API 按业务域校验，越权返回 403；
4. 工作台聚合数据按当前登录角色裁剪。

> 纯前端权限只用于界面演示，不构成真实安全边界。当前仍有少量接口的数据范围未完全收口，见「12. 当前限制与已知差距」。

## 5. 核心业务功能

### 5.1 登录与后台框架

- 淡蓝渐变 + 点阵背景登录页，白色圆角卡片、演示账号登录。
- 登录后按 token 复原员工与角色，刷新不丢失身份。
- 深色侧栏支持分组、折叠、当前项高亮；顶栏含面包屑、刷新、用户区退出。
- 多标签页可关闭，关闭当前页自动回到相邻页；404 与 403 页面完整。

### 5.2 分角色工作台

- 登录后进入角色工作台，而不是所有功能的平铺入口。
- KPI 卡按角色变化：管理员看全院指标，医生看本人待接诊/待报告，收费员看待收费/待发药/待结算，住院角色看入科/医嘱/结算。
- 队列卡展示待处理业务，点击可进入对应业务页面。
- 右侧固定展示「我的待办」「系统提醒」「明日运营预测」「快捷入口」。
- 管理员额外嵌入原首页运营概览（指标卡 + 近七日双轴图 + 床位环图）。

### 5.3 基础资料

- **科室管理**：科室编码、名称、电话、负责人、状态；删除有引用保护。
- **员工管理**：姓名/账号/电话/类型/科室/角色筛选；新增、批量删除、导出；账号启停、修改、重置密码；被业务引用时禁止删除。
- **病区管理**：病区编码、名称、所属科室、楼层、护士长、状态。
- **床位管理**：病区/床号/类型/状态/启用筛选；占床保护；与入院登记联动。
- **收费项目**：项目编码、名称、类型、单价、状态。
- **药品目录**：药品编码、名称、规格、单位、单价、库存、状态。
- **检验检查项目**：项目编码、名称、类型、单价、状态。
- **批次库存**：药品、批号、数量、有效期；与发药扣减、临期提醒联动。

### 5.4 患者服务

- **患者档案**：患者编号、姓名、性别、电话、出生日期、过敏史、状态；支持编号/姓名/电话筛选、CRUD、导出。
- **患者 360° 时间线**：以患者为主线，聚合挂号、接诊、处方、检查、报告、收费、入院、入科、医嘱、出院结算，以及转床/取消登记/申请出院等关键事件。
  - 每个节点展示时间、科室、角色、业务摘要、当前状态；
  - 支持时间正序/倒序、按环节多选筛选；
  - 顶部展示当前诊疗进度（已完成 / 共 N 个环节 / 待处理）；
  - 点击节点查看详情，并可跳转到原始业务记录；
  - 页面只读，不修改业务数据。

### 5.5 门诊管理

- **医生排班**：按日期范围查看排班，科室卡片网格；同医生同日同时段冲突禁止提交；已产生挂号的排班不可删除/改期。
- **门诊挂号**：仅可选择有排班的医生；支持新增、退号退款、导出；挂号状态与收费状态分离。
- **门诊接诊**：大弹窗录入主诉、现病史、诊断、处理意见；处方明细与医技申请支持动态增删行，金额自动汇总；退号记录不可接诊。
- **处方查询**：按患者/医生/日期等条件查询处方明细。
- **医技申请**：查看已开立的检查检验申请及报告状态；支持分页前过滤，历史待报告记录可见。
- **门诊收费**：对已接诊业务收费，生成收费小票；收费后才允许发药。
- **处方发药**：按已收费处方发药，自动扣减批次库存；库存不足有校验。
- **医技报告**：为检查检验申请出具报告；报告完成后对应提醒自动消失。

### 5.6 住院管理

- **入院登记**：登记时占用空闲床位；支持入科确认、转科转床、取消登记、导出；取消登记释放床位。
- **住院医嘱**：开立、执行、作废医嘱；执行后对应提醒自动完成。
- **出院结算**：汇总住院费用、预交金抵扣、结算差额；结算后释放床位。
- 数据层保证：同一床位不可同时分给两名在院患者；同一患者不可重复在院登记。

### 5.7 系统管理

- **用户角色**：角色名称、编码、描述、菜单权限；角色被员工引用时禁止删除。
- **菜单权限**：按角色勾选可见菜单，保存后影响侧栏与路由守卫。
- **操作日志**：展示历史操作日志，兼容旧数据结构。
- **审计中心**：结构化审计查询、before/after 差异、按业务对象回放；只读，无删除/重放执行入口。
- **演示数据重置**：恢复最新版种子数据；重置前有确认提示。

## 6. 智能化能力

### 6.1 智能待办

- 用户填写标题、描述、关联模块、截止时间，创建个人待办。
- AI 根据截止时间与关联模块给出**优先级建议（高/中/低）+ 理由 + 处理建议**。
- 用户可以采纳建议，也可以手动调整优先级；采纳会写入 AI 审计。
- 待办支持完成/恢复、编辑、删除、状态/模块/优先级/关键字筛选、按截止时间/优先级/创建时间排序。
- 当前 AI 为本地确定性规则引擎，不是外部大模型。

### 6.2 系统提醒

系统按明确的数据规则实时计算提醒，**问题解决后提醒自动消失；确认/暂缓只改变展示状态，不代表问题已解决**。

| 规则 | 触发条件 | 处理入口 |
| --- | --- | --- |
| 药品库存偏低 | 启用药品库存低于阈值（默认 50） | 药品目录 |
| 床位占用率过高 | 全院床位占用率高于阈值（默认 80%） | 床位管理 |
| 检查报告待处理 | 有医技申请但未出报告 | 医技报告 |
| 处方待发药 | 已收费且未发药 | 处方发药 |
| 住院医嘱待执行 | 存在未执行医嘱 | 住院医嘱 |
| 药品批次临近有效期 | 距有效期不足 30 天 | 批次库存 |
| 挂号未缴费 | 待分诊且未缴费 | 门诊挂号 |

每条提醒展示级别、触发原因、关联业务和处理入口；支持按级别/确认状态/关键字筛选，并提供 AI 解释（只解释触发依据，不改变提醒状态）。

### 6.3 操作审计与流程回放

- 关键写操作自动写入 `auditEvents`，记录：操作人、角色、时间、动作、业务类型、对象编号、结果、状态变化摘要、before/after 快照。
- 覆盖挂号、退号、接诊、门诊收费、处方发药、出具报告、入院登记、入科确认、转科转床、取消登记、申请出院、出院结算、医嘱开立/执行/作废，以及基础资料与系统配置变更。
- 审计中心支持关键字、操作人、角色、业务类型、动作、时间范围筛选；详情展示字段级前后差异；可按业务对象查看只读操作时间线。
- 审计集合只读：没有删除接口，也不提供重放执行；审计数据剔除密码等敏感字段。

### 6.4 患者 360° 时间线

见「5.4 患者服务」。时间线面向**诊疗进度**，审计回放面向**操作追溯**，两者可共用业务记录但视角不同。

### 6.5 AI 智能中心

系统注册 12 个只读 AI 任务：

| 任务 | 名称 | 用途 |
| --- | --- | --- |
| `system.selftest` | 系统自检 | 检查 AI 基础设施与护栏状态 |
| `todo.priority` | 待办优先级建议 | 结合截止时间与关联模块排序并解释 |
| `reminder.explain` | 系统提醒解释 | 解释提醒触发依据与处理建议 |
| `assistant.qa` | Ask Astra 业务助手 | 自然语言只读问答：结论 + 数据依据 + 建议入口 + 免责 |
| `report.summary` | 智能报表 | 收入结构、科室工作量、医生接诊量、药品消耗、床位周转，含 AI 摘要与 CSV 导出 |
| `record.structure` | 病历结构化 | 自由文本提取症状、诱因、过敏、风险提示；不覆盖原文，人工确认后走原业务校验 |
| `anomaly.explain` | 运营异常分析 | 识别停用床位、低库存、报告积压、医嘱/发药积压、临期、占用率等异常并给出处理入口 |
| `forecast.outpatient` | 次日门诊量预测 | 基于近 7 日数据的确定性统计口径，含区间与说明 |
| `forecast.beds` | 次日床位需求预测 | 同上 |
| `forecast.discharge` | 未来 3 日预计出院 | 同上 |
| `forecast.backlog` | 次日医嘱/发药积压 | 同上 |
| `forecast.noshow` | 挂号爽约风险率 | 同上 |

**AI 安全边界（Guardrails G1–G7）**：

- G1：AI 层无业务写能力，只读分析与建议；
- G2：输出结构校验，失败时回退「无建议」；
- G3：强制注入免责声明；
- G4：上下文脱敏，不传密码、手机号、token；
- G5：角色权限收敛，AI 只看到当前角色可见数据；
- G6：AI 总开关关闭后入口返回 503，不写审计、不改数据；
- G7：默认零外部网络，外部 LLM 仅保留骨架且默认禁用。

每次 AI 调用写入 `aiEvents`（任务、输入摘要、输出、耗时、置信度、是否采纳），可在 AI 治理中心查看。

## 7. 业务规则与状态流转

```text
患者档案
  └─► 门诊挂号（必须有排班）
        ├─► 退号退款（退号后不可接诊）
        └─► 门诊接诊
              ├─► 处方 ─► 门诊收费 ─► 处方发药（扣批次库存）
              └─► 医技申请 ─► 门诊收费 ─► 医技报告
                    └─► 接诊建议住院
                          └─► 入院登记（占用空闲床位）
                                └─► 入科确认
                                      ├─► 转科转床（释放原床 + 占用新床）
                                      └─► 住院医嘱（开立/执行/作废）
                                            └─► 出院结算（释放床位）
```

关键约束：

- 同医生同日同时段排班冲突禁止提交；
- 已产生挂号的排班不可删除/改期；
- 同一床位不可同时分给两名在院患者；
- 同一患者不可重复在院登记；
- 收费前不可发药；发药后扣减库存；
- 结算后释放床位；
- 所有金额在数据层以**整数分**存储与计算，界面以元格式化，避免浮点误差。

## 8. 数据、存储与安全设计

| 项 | 说明 |
| --- | --- |
| 存储键 | `localStorage.astra_hospital_db_v1` |
| 当前数据版本 | `CURRENT_VERSION = 5` |
| 迁移策略 | v1→v5 逐级增量迁移；迁移前先备份到 `astra_hospital_db_v1_backup_v<版本>`；只增不删；拒绝降级 |
| 金额 | 整数分存储，`utils/money.js` 统一格式化 |
| 业务审计 | `auditEvents`，记录真实操作人/角色/前后状态，剔除密码 |
| AI 审计 | `aiEvents`，append-only，记录每次 AI 调用与采纳状态 |
| Mock 失败模拟 | 请求头 `x-mock-fail: 1` 返回 500 且不落库，用于验证失败安全 |
| 数据重置 | 侧栏「演示数据重置」或顶部用户菜单；重置为最新版种子数据 |

## 12. 当前限制与已知差距

1. **纯前端演示**：权限、Mock API、localStorage 均不是生产级安全边界；不处理真实患者数据。
2. **AI 为本地确定性规则引擎**：不是外部大模型；如需接入真实 LLM，需要后端/代理与密钥管理，且必须保留只读、审计、脱敏、开关等护栏。
3. **待办数据范围**：待办中心当前加载全部待办，Mock 接口未强制按 `ownerStaffId` 校验归属；工作台面板已按当前用户过滤。
4. **审计接口权限**：`/api/audit-events` 被归入 `home` 域，任意登录角色可直接调用；菜单与路由层已限制为管理员。
5. **审计回放维度**：审计中心按业务对象回放，暂不支持直接按患者聚合；患者维度可使用患者 360° 时间线，但时间线不含操作人与 before/after。
6. **审计结果**：仅记录成功操作，失败/被拒绝的操作没有审计记录。
7. **管理员待审核队列**：系统没有审批业务，管理员工作台以运营队列、库存与提醒为主。
8. **E2E 环境要求**：需要系统 Edge/Chrome 与完整权限；受限沙箱下浏览器多进程可能无法启动。
